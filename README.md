# Graph Fraud Command Center

Real-time transaction scoring: 14 graph-context features computed from a live NetworkX store, fused by a hand-tuned heuristic and a PyTorch MLP, returned with reason codes.

**[Live demo](https://stelioszach.com/demos/fraud-graph/)**

## Results

Load test of the scoring path. **Conditions, so the number means something: single container on `http://localhost:18910`, in-memory NetworkX graph store, no database, no network hop, run 2026-02-28.** This is not a distributed or production-traffic figure.

| Metric | Value | Evidence |
|---|---|---|
| Requests | 2,500 (0 errors, 100% success) | [`benchmarks/benchmark_2026-02-28.json`](benchmarks/benchmark_2026-02-28.json) |
| Throughput | 457.4 req/s | same |
| Latency p50 / p95 / p99 | 1.99 / 3.27 / 4.82 ms | same |
| Graph features per event | 14 | [`app/services/feature_engineering.py`](app/services/feature_engineering.py) |

No detection-quality number is published here. `make eval` writes `benchmarks/quality_latest.json` locally and it is deliberately **not** committed: the only labels available come from `_label_rule()` applied to this repo's own simulator, so the resulting precision/recall measures agreement between the scorer and a hand-written rule on synthetic data — not accuracy.

## Run

```bash
cp .env.example .env
make setup && make train      # trains the MLP on synthetic data, ~15 s
make run                      # uvicorn on :8090
make smoke && make benchmark

python3 scripts/benchmark.py --base-url http://localhost:18910 --requests 2500
```

Docker: `docker compose -f docker-compose.vps.yml up -d --build` exposes API `18910`, Prometheus `18920`, Grafana `18930`. Scoring is `POST /api/v1/score`; the service also exposes `/api/v1/graph/neighborhood/{id}`, `/api/v1/alerts` and 11 Prometheus metrics on `/metrics`.

## Limitations

- **All data is synthetic**, generated by `app/services/simulator.py`. No real transaction data has passed through this service.
- **`EdgeMLP` is a plain MLP over the 14 engineered edge features, not a message-passing GNN.** There is no PyG or DGL here, and it is trained on synthetically generated ring patterns.
- **No detection-quality claim**, for the reason above.
- The benchmark is single-container, in-memory, localhost, with no concurrency beyond the load script.
- State is in-process: restarting the API empties the graph. There is no persistence layer.
- The model is blended at weight 0.15 with `uplift_only`, so it can only raise a score, never suppress a rule signal — a deliberate constraint, not a tuned optimum.
